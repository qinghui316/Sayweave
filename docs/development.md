# 开发与构建

## 本地开发与同步

单人开发按「本地短期开发分支 → 本地验证和独立审查 → 合入本地 `main` → 直接推送远端 `main`」执行。每项工作从当前本地 `main` 新建 `codex/<工作名>` 分支；开发和临时审查候选保留在本地，完成后清理临时审查分支。需要保留的历史提交使用明确的本地归档引用。

完成项目 Harness 的本地 I2 合入后执行 `git push origin main`。同步前核对远端主线；若远端出现新提交，先处理差异。已完成的远端临时分支，只在其内容和必要历史引用已保留、主线同步成功后，按核对时的完整提交号逐条清理。不要复用旧开发分支上传新候选。

普通分支推送不触发 CI；面向 `main` 的 PR 和明确手动请求运行 CI。所有者的 CI 例外仅用于日常主线直推，合入外部 PR 仍须等待 GitHub Actions 的 `CI` 通过。对管理员生效的线性历史、禁止强推和禁止删除保护继续保留。正式版本标签使用独立发布流程，见 [发布说明](release.md)。

## Windows 环境

- Node.js 24 与 npm（版本约束见 package.json）。
- Rust，通过 rustup 安装；项目 rust-toolchain.toml 固定工具链及 MSVC 目标。
- Visual Studio 2022 C++ Build Tools，包含 Windows SDK 和桌面 C++ 工具。
- Microsoft Edge WebView2 Runtime。

将 Node、npm、Cargo 与 rustup 放入当前终端 PATH，确认 `node --version`、`npm --version`、`cargo --version`、`rustup show` 可用。不要提交个人工具安装路径。

## 启动

在项目根目录执行：

```powershell
npm ci
npm run desktop:dev
```

Vite 使用 127.0.0.1 的固定端口；端口占用时报错。前端修改热更新，Rust 修改需要重新编译。结束开发使用启动终端的 Ctrl+C；应用内托盘退出关闭该应用。

浏览器辅助开发使用 `npm run dev`。浏览器适配器不提供原生窗口或磁盘词典持久化。开发组件页面只在开发模式开放，正式构建没有该入口。

模型面板在桌面开发版使用真实系统凭据和磁盘配置；浏览器只模拟数据与测试结果。文字测试会向填写的服务发出真实短请求，可能产生少量费用；保存不会自动测试。实现和恢复规则见 [models.md](models.md)。

项目代理的检查分层、范围选择与证据复用见 [本地 Harness Verify 工作流](../.agents/skills/beaver-4a20fc43577a-harness/references/workflows/verify.md)；现有单项命令及桌面工具见 [测试说明](testing.md)。npm 与 Cargo 锁文件固定依赖；不为每次启动重复安装。

## 构建

```powershell
npm run build
npm run desktop:build
```

桌面 dev/build 包装分别构建固定 TSF 代理和核心，通过构建期变量嵌入主程序；未变化且来源、工具链和哈希匹配的产物从 `.local/text-service-build` 复用。代理 ABI 独立管理，普通核心变更不替换其已认可字节；构建仍执行 `tauri build --no-bundle`。通常生成 `src-tauri/target/release/sayweave.exe`；显式 `--target x86_64-pc-windows-msvc` 时位于对应目标子目录。关闭开发服务后可以独立运行。普通源码／日常构建使用开发渠道，禁用公开自动更新；正式签名安装包和隔离更新验收见 [发布说明](release.md)。

安装器自动部署匹配的输入组件并核验登记，首次没有启停选择时启用，覆盖升级保留显式启停选择。机器维护经 Windows UAC 确认，由包内固定维护入口操作受保护的 Program Files 目录；用户启用由原普通用户进程处理，不替换默认键盘输入法。正常设置不显示输入组件状态、启停开关或管理菜单；仅输入不可用时，在「设备与快捷键」提供原生允许的恢复操作，复用公共按钮与提示。先前显式停用的选择继续保留，恢复启用需要用户点击。未完成的安装事务需重新运行安装包恢复，期间不能叠加手动组件操作。代理和核心使用 DLL 内容哈希目录，保留已映射的旧版本。首次由直接核心迁移至代理需要重开宿主一次；后续兼容核心更新在下一轮准备时核验并切换，代理本身升级仍可能需要重开。受控编辑器和实际 Codex 的两次连续更新证据分别记录，见 [输入契约](dictation.md)。移除持久记录意图，核对已有登记后注销并删除当前核心描述；仍被使用的组件文件保留待清理事实，由维护流程处理。直接 Cargo 检查不嵌入安装载荷，仍能使用已安装的组件；标准桌面命令负责可交付程序的载荷。

### 登录 Windows 后启动

正式安装器在安装事务提交并核验成功后，为安装用户一次性登记 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 中的 `Sayweave`：带引号的安装 EXE 普通盘符绝对路径加私有参数 `--autostart`。安装事务内部保留规范化文件路径，生成启动命令时转换其本地盘符表示。产品键的 `LoginStartupInitialized` 标记完成后，保留用户通过 Windows「设置 → 应用 → 启动」或任务管理器关闭、删除或替换启动项的选择；安装维护仅允许将完整匹配本安装旧版生成命令的扩展路径表示修正为普通路径，并读回核验，不修改 Windows 启动审批记录。日常运行不维护启动登记，正确命令不重复改写。正常退出仅结束本次运行。启动登记警告独立于安装成功结果；辅助程序返回2时，安装器不回滚已提交程序。卸载完成后只清理指向本安装、参数为空或仅为 `--autostart` 的启动值。

登录启动隐藏主窗口并驻留托盘，初始化原有设置和快捷键，不自动录音；托盘打开主界面。重复的 `--autostart` 进程在原单实例锁处静默退出。开发渠道不登记生产启动项。原生窗口验证可用已有 `scripts/test-desktop.ps1 -Autostart`，使用隔离资料，检查隐藏、焦点、托盘与重复启动；真正的 Windows 登录验证单独记录。

## 数据与资源

桌面包装按需构建独立工作程序及 CPU/Vulkan DLL，主程序和安装辅助程序不链接推理库。首次 Windows 构建可运行 `node scripts/setup-local-asr-tools.mjs`，固定校验后只准备最小 Vulkan 编译工具；已有 SDK 或本机工具直接复用。终端用户不需要 Python、CUDA、SDK 或编译器。`node scripts/build-local-asr.mjs --debug` 在原 Cargo target 下复用按来源与哈希核验的运行载荷，不新建工作树或复制依赖目录。

桌面安装载荷包括 `local-asr/` 中明确列出的工作程序、后端 DLL、CRT 和许可证；清单位于 `src-tauri/local-asr-protocol/runtime-files.json`。安装备份、恢复和卸载使用同一文件身份，更新前先结算子进程。权重位于各自资料目录的 `models/`，不属于安装器载荷或卸载清单。本地识别已随0.1.19交付，实际模型、宿主和人声试用按原身份及范围留证，构建成功不替代使用验收。

字体随依赖打包，普通构建不访问在线字体。开发和发布使用不同的数据子目录，详见 [本地数据](local-data.md)。不要在用户数据目录运行破坏性测试。

提交前检查 `npm run check:distribution`，审核新增源码和文档的用途；测试生成的 `.local/`、截图、报告、数据库及构建产物保留在本地。

核心迁移试用前保留一份明确身份的原开发程序及组件／登记快照。兼容核心更新的原始回退锚点随原生组件更新账本保留；固定 `--sayweave-text-service=rollback --initiator=<当前用户SID>` 入口仅在机器维护锁内恢复与当前嵌入载荷对应的已知事务，不接受外部 DLL 路径。回退后通过原启动入口恢复已验证程序；已经持有代理／旧核心对象的宿主可能仍需手动重开一次。

本地识别将原生来源证明、处理分段就绪和输入写权分开。工作程序以16kHz/20ms PCM运行Quality VAD，实际连续800ms非语音只发布停顿事实，不结束或重建推理流。私有协议2绑定任务、停顿采样位置和原生修订。本地适配在原生证明后统一处理汉字内部ASCII空格；实时全文继续发布，整理确认使用停顿、明确标点、512字符安全分段预算或最终结果。现有活动块容量、Draft、学习及输入核心保持。受控语料、实际模型、宿主正文与用户麦克风反馈分别记录；0.1.20翻译的正式升级试用按独立发行记录结算。
