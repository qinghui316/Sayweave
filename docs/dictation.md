# Windows 跨应用口述

口述快捷键默认是右 Alt。在设置的「设备与快捷键」中，可录入单键或组合键，选择按一次开始／结束，或按住说话／松开结束。界面分别显示保存值与实际启用值；任务中保存的设置在当前任务释放后注册。

## 职责与任务边界

`shortcuts` 将 Windows 物理键状态与官方组合键注册转换成带配置代次、按键代次的事件。右 Alt 与 AltGr、左右修饰键分开，忽略注入键和长按重复；活动按键期间补充释放检查。设置录入有超时、关闭和页面重载清理。

快捷键状态快照带单调序号，读取和命令响应与事件使用相同顺序；设置和首页只接受新快照。每次录入携带独立随机身份，原生状态在录入结束后仍保留该身份，设置只消费当前编辑器拥有的录入。放弃、关闭或离开后，旧捕获结果不会进入下次草稿，准备期间收到其他状态也不会清除本次录入归属。

`dictation` 在异步准备前预约任务身份，绑定来源与原生目标，接续 SpeechService 的终结结果。应用内试说、历史重识别与外部口述共用准入；外部任务直到交付结束才释放。控制和当前录音重试绑定显示任务 ID；悬浮展示使用独立 presentationId，关闭和复制同时绑定任务及展示身份；按键同时绑定触发时的任务与准入代次。配置注册和落库期间暂停新准入，旧配置事件、旧 Esc 与旧终结结果不能控制新任务。

SpeechService 拥有录音和识别生命周期；供应商适配器、音频文件和历史职责保持独立。Runtime 管理窗口阶段投影。前端只显示状态，不决定输入目标或供应商协议。

`windows_input` 在专用 MTA 线程探测目标与输入。窗口、进程生命周期、控件、选区和必要的局部文字证据只保留在原生内存，不发送给供应商、前端、日志或数据库。UIA COM 对象与事件订阅留在该线程并成对释放。

## 悬浮展示与正常结束

点按和按住均在按下时立即展示“准备录音”，服务与设备就绪后才显示录音状态。点按再次按下结束，按住松开结束；准备中提前结束则取消启动。采集对象在等待设备准备前建立停止归属，取消后迟到的准备不能启动麦克风。

正常结束停止采集、排空已采集 PCM、发送协议结束指令并继续接收最终结果。悬浮反馈依次为“识别中”“正在填入”“已填入”。确认填入后停留约600ms并收起；已提交但无法确认时提示“请确认输入结果”，不会重复提交或展示复制框。提示可关闭，也在短暂停留后收起；剪贴板恢复失败仍保留重试入口。没有输入目标的结果框保持可复制和可关闭，复制成功后短反馈收起。

关闭展示不删除历史，也不取消仍在运行的识别。新任务有新的展示身份，旧关闭和定时器失效。字幕只用于录音阶段，最终反馈不依赖正文是否存在。后台识别和展示隐藏分别管理。

音量从本地采集的50ms窗口聚合，独立于网络发送发布；波形以20Hz更新真实音量，快速上升、平缓回落。减少动态时保留音量变化，隐藏或结束后停止绘制。

## 输入与剪贴板

开始时捕获外部前台目标，完成后复核。识别到可输入目标时，只展示语音反馈；目标变更、权限不足、输入法组合输入或交付失败时，结果保留在应用内并展示简短提示。没有识别到可靠输入目标时，展示带复制和关闭操作的结果框。不会强制切回旧窗口。原生 Edit 使用定向粘贴；可验证的 UIA 编辑控件使用一次模拟粘贴。已有选区按普通粘贴替换。

目标事件使用系统事件时间过滤捕获之前排队的通知；与捕获落在同一系统时钟粒度内的变更停止自动填入。输入后读取完整文字及对应光标位置确认，使用 UTF-16 边界并统一换行表示；提交事件不等同于确认填入。取消与提交通过一个原子边界协调，已经提交的输入不自动重试，也不承诺撤回。输入失败不改写识别成功状态。 交付尚未得到结果时，悬浮窗保持处理反馈；识别成功后的取消只停止填入，保留文字。TextPattern 目标需要可编辑属性的精确布尔证明；缺失、混合或查询失败均停止自动填入。

自动粘贴和显式复制共用串行工作线程。自动粘贴备份已支持的文本、DIB、PNG、文件列表、HTML、RTF 与排除标识，保护总量为 32 MiB；未知或超限格式停止自动填入并保留原剪贴板。临时文字携带随机操作标识及 Windows 历史／云同步排除标识。恢复同时检查操作标识和剪贴板序号，用户的新复制优先。恢复失败保留内存备份，提供受控重试，不重新填入。

Windows 延迟渲染可能在 `GetClipboardData` 内等待外部应用。备份采用单个只读辅助线程，调用方最多等待 500ms，迟到结果不能执行输入或写剪贴板。退出协调最多等待 5 秒；进程退出后不重放输入、不覆盖当前剪贴板。依据：[微软剪贴板操作](https://learn.microsoft.com/en-us/windows/win32/dataxchg/clipboard-operations)、[延迟渲染等待](https://devblogs.microsoft.com/oldnewthing/20220609-00/?p=106731)。

## 数据与权限

迁移 006 新增快捷键设置和交付尝试；001–005 保持冻结。设置使用版本检查。交付记录只保存关联识别尝试、状态、时间与稳定错误码，不重复保存正文、目标或剪贴板。历史关闭时交付只在内存中。历史启用但存档／交付登记失败时停止填入，保留应用内结果。

启动恢复将 pending／delivering／submitted 标为无法确认，不重复输入。历史展开区按识别版本查看填入结果；列表继续展示识别内容。

主窗口可管理快捷键和读取历史交付；悬浮窗仅操作当前任务、复制当前结果及重试本应用待恢复的剪贴板。前端没有通用 UIA、任意 HWND、任意路径或剪贴板读取入口。悬浮窗不可聚焦；显示、字幕更新和窗口显隐不改变任务目标。 Windows 显隐统一走非激活原生入口，尺寸／位置继续使用非激活路径；创建后不修改悬浮窗的聚焦、装饰、置顶或最大化标志，避免底层窗口库的可见状态覆盖原生显隐。

## 验证

`npm run check` 与 `npm run test:e2e` 检查类型、组件、契约、生命周期和既有流程。`npm run test:input` 在自己启动的空白编辑器检查真实插入、选区替换、UTF-16、读回、剪贴板格式及恢复故障，不复用个人文档。`npm run test:desktop` 使用独立 UUID 数据目录验证窗口与退出。

实际兼容性按 Windows 控件和应用版本分别登记。隔离原生编辑器、浏览器界面测试与供应商口述是三类证据；一种通过不能代替另外两种。个人截图、性能记录和供应商验收留在本地 Change 中，未完成的项目不得标为已通过。
