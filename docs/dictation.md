# Windows 跨应用口述

口述快捷键默认是右 Alt。在设置的「设备与快捷键」中，可录入单键或组合键，选择按一次开始／结束，或按住说话／松开结束。点击键位框直接录入，组合键分别显示；Esc、点击框外或窗口失焦退出录入，保留原设置。保存前仍为草稿。界面分别显示保存值与实际启用值；任务中保存的设置在当前任务释放后注册。

同时使用其他口述工具或输入法快捷键时，为各工具设置不同键位。组合键注册可以报告系统注册冲突；单独修饰键监听成功只表示监听已启动，不能检测其他程序是否拦截了同一按键。

## 职责与任务边界

`shortcuts` 将 Windows 物理键状态与官方组合键注册转换成带配置代次、按键代次的事件。右 Alt 与 AltGr、左右修饰键分开，忽略注入键和长按重复。自行消费的按键以实际 hook 松开事件结束；活动组合键中未消费的成员补充异步状态检查。每次按键的消费归属在捕获失焦等提前返回之前结算。设置录入有超时、关闭和页面重载清理。

快捷键状态快照带单调序号，读取和命令响应与事件使用相同顺序；设置和首页只接受新快照。每次录入携带独立随机身份，原生状态在录入结束后仍保留该身份，设置只消费当前编辑器拥有的录入。放弃、关闭或离开后，旧捕获结果不会进入下次草稿，准备期间收到其他状态也不会清除本次录入归属。

`dictation` 在异步准备前预约任务身份，绑定来源与原生目标，接续 SpeechService 的终结结果。应用内试说、历史重识别与外部口述共用准入；外部任务直到交付结束才释放。控制和当前录音重试绑定显示任务 ID；悬浮展示使用独立 presentationId，关闭和复制同时绑定任务及展示身份；按键同时绑定触发时的任务与准入代次。配置注册和落库期间暂停新准入，旧配置事件、旧 Esc 与旧终结结果不能控制新任务。

SpeechService 拥有录音和识别生命周期；供应商适配器、音频文件和历史职责保持独立。Runtime 管理窗口阶段投影。前端只显示状态，不决定输入目标或供应商协议。

`windows_input` 在专用 MTA 线程探测目标与输入。窗口、进程生命周期、控件、选区和必要的局部文字证据只保留在原生内存，不发送给供应商、前端、日志或数据库。UIA COM 对象与事件订阅留在该线程并成对释放。

## 悬浮展示与正常结束

点按和按住均在按下时立即展示“准备录音”，服务与设备就绪后才显示录音状态。点按再次按下结束，按住松开结束；准备中提前结束则取消启动。采集对象在等待设备准备前建立停止归属，取消后迟到的准备不能启动麦克风。

正常结束停止采集、排空已采集 PCM、发送协议结束指令并继续接收最终结果。悬浮反馈依次为“识别中”“正在填入”“已填入”。确认填入后停留约600ms并收起；已提交但无法确认时提示“请确认输入结果”，不会重复提交或展示复制框。提示可关闭，也在短暂停留后收起；剪贴板恢复失败仍保留重试入口。没有输入目标的结果框保持可复制和可关闭，复制成功后短反馈收起。

关闭展示不删除历史，也不取消仍在运行的识别。新任务有新的展示身份，旧关闭和定时器失效。字幕只用于录音阶段，最终反馈不依赖正文是否存在。后台识别和展示隐藏分别管理。

音量从本地采集的50ms窗口聚合，独立于网络发送发布；波形以20Hz更新真实音量，快速上升、平缓回落。减少动态时保留音量变化，隐藏或结束后停止绘制。

## 输入与剪贴板

开始时捕获外部前台目标，完成后复核。文字填入并确认后，悬浮窗显示短反馈并收起。明确未提交且有文字时，提供复制和关闭；已经提交或提交情况不确定时，提示检查输入结果并收起。不会强制切回旧窗口。原生 Edit 使用定向粘贴；UIA 编辑控件使用一次模拟粘贴。已有选区按普通粘贴替换。

目标身份、可写性、变化保护和回读能力分别评估。可写 ValuePattern 或当前编辑范围的只读属性用于确认可写性，整份富文本文档的混合属性不代表当前光标不可编辑。TextPattern 以2048个 UIA 字符单位取得周边范围，读取上限为每侧8192个 UTF-16 单元；全文读取和变化监听不再共同作为可写性条件。回读不足时，使用可用的选区、焦点、目标事件与物理编辑活动保护位置；证据不足返回具体原因。

目标事件过滤捕获之前排队的通知。光标几何位置通知只表示显示变化，文本位置由选区、范围及编辑活动复核；焦点、正文和选区变更继续失效目标。提交前复核窗口、进程生命周期、控件、选区及内容。原生 Edit 使用 UTF-16 选区。UIA 使用捕获的范围起点到当前光标之间的实际文字做精确确认，统一换行表示；不把供应商定义的 Character 单位当作 UTF-16 偏移。[微软文本单位说明](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-uiautomationtextunits)。无法回读时保留最多500ms消费窗口后按所有权恢复剪贴板。提交、确认和恢复分别返回结果；部分模拟事件提交后不自动换策略。输入失败不改写识别成功状态。取消与提交有一个原子边界，已经提交的输入不自动重试，也不承诺撤回。

快捷键与输入使用共享的物理按键证据；系统逻辑修饰键状态与物理事件矛盾时返回 `keyboardStateConflict`。该状态不表示用户仍按着某个键。交付期间不强行释放用户或其他工具的按键。

自动粘贴和显式复制共用串行工作线程。自动粘贴备份已支持的文本、DIB、PNG、文件列表、HTML、RTF 与排除标识，并原样保留 Chromium 文本附带的来源 URL／RFH 标识等已知内存格式；保护总量为 32 MiB；未知或超限格式停止自动填入并保留原剪贴板。临时文字携带随机操作标识及 Windows 历史／云同步排除标识。恢复同时检查操作标识和剪贴板序号，用户的新复制优先。恢复失败保留内存备份，提供受控重试，不重新填入。

Windows 延迟渲染可能在 `GetClipboardData` 内等待外部应用。备份采用单个只读辅助线程，调用方最多等待 500ms，迟到结果不能执行输入或写剪贴板。退出协调最多等待 5 秒；进程退出后不重放输入、不覆盖当前剪贴板。依据：[微软剪贴板操作](https://learn.microsoft.com/en-us/windows/win32/dataxchg/clipboard-operations)、[延迟渲染等待](https://devblogs.microsoft.com/oldnewthing/20220609-00/?p=106731)。

## 数据与权限

迁移 006 新增快捷键设置和交付尝试；001–005 保持冻结。设置使用版本检查。交付记录只保存关联识别尝试、状态、时间与稳定错误码，不重复保存正文、目标或剪贴板。历史关闭时交付只在内存中。历史启用但存档／交付登记失败时停止填入，保留应用内结果。

启动恢复将 pending／delivering／submitted 标为无法确认，不重复输入。历史展开区按识别版本查看填入结果；列表继续展示识别内容。

主窗口可管理快捷键和读取历史交付；悬浮窗仅操作当前任务、复制当前结果及重试本应用待恢复的剪贴板。前端没有通用 UIA、任意 HWND、任意路径或剪贴板读取入口。悬浮窗不可聚焦；显示、字幕更新和窗口显隐不改变任务目标。 Windows 显隐统一走非激活原生入口，尺寸／位置继续使用非激活路径；创建后不修改悬浮窗的聚焦、装饰、置顶或最大化标志，避免底层窗口库的可见状态覆盖原生显隐。

## 验证

`npm run check` 与 `npm run test:e2e` 检查类型、组件、契约、生命周期和既有流程。`npm run test:input` 在自己启动的空白编辑器检查真实插入、选区替换、UTF-16、读回、剪贴板格式及恢复故障，不复用个人文档。`npm run test:desktop` 使用独立 UUID 数据目录验证窗口与退出。

`scripts/test-speech-desktop.mjs` 验证录音到交付的原生受控闭环。可编辑的 input、textarea、contenteditable 和 ProseMirror 必须实际得到预期文字；被拒绝或出现复制结果不能代替成功断言。测试依赖的 ProseMirror 包仅用于受控目标，不进入产品页面。

实际兼容性按 Windows 控件和应用版本分别登记。隔离原生编辑器、浏览器界面测试与供应商口述是三类证据；一种通过不能代替另外两种。个人截图、性能记录和供应商验收留在本地 Change 中，未完成的项目不得标为已通过。

## 状态接续与扩展

SpeechService 通过原生 watch 订阅输出生命周期，通过终结通道交付最终结果。启动层连接口述协调器与 Runtime 投影；语音服务不调用具体口述协调器。历史服务拥有交付记录和启动恢复，快捷键服务只管理触发配置。口述协调器在资源整理和任务准入释放后发布可操作的结果展示。显示与收起使用任务和展示身份，旧操作不能作用于新任务。

平台输入只交付本轮最终识别原文。后续草稿模块管理临时文字、用户编辑和版本；处理模块输出绑定原文版本的独立结果；平台组合输入能力管理临时范围的更新、提交和取消；发送模块管理发送动作与口述轮次。原始识别记录保持独立，处理失败或用户修改不覆盖它。本轮没有实现这些后续模块。
